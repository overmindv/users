# Доставка аватаров

OVM-271: `avatar_version` увеличивается транзакционно при смене аватара или
статуса удаления. Триггер создаёт событие. Worker доставляет актуальный снимок
Users, а не исторический payload. Media сохраняет версию даже для null-привязки.
Одинаковая версия с другим файлом — конфликт; меньшая версия — безопасный no-op.

Lease — 5 минут, deadline итерации — 30 секунд. Завершение и retry проверяют
attempt и живую lease. После восьми попыток событие получает failed; backoff
2–256 секунд. Ответ Media не сохраняется в last_error и не попадает в worker log.
`users_avatar_outbox_exhausted` — количество сохранённых failed событий, включая
исторические, уже заменённые новым аватаром. Метрика обновляется раз в минуту.

Раз в минуту worker обходит до 100 пользователей по UUID и восстанавливает
отсутствующие события текущей версии. Failed автоматически не перезапускаются.
Обход включает удалённых пользователей: их текущая привязка всегда null.
Это восстановление потерянной доставки, а не инвентаризация S3 или OVM-180.

После устранения причины оператор в БД Users может вызвать:

```sql
SELECT users_replay_avatar('00000000-0000-0000-0000-000000000001'::uuid);
```

Заменить UUID нужным пользователем. Функция берёт блокировку Users, возвращает
существующее активное событие либо создаёт новое с текущей версией. Старый payload
не копируется. EXECUTE не выдан PUBLIC; использовать владельца приложения или
явно выдать право его DB-роли. Нельзя обнулять attempts старой running записи.

Порядок rollout: миграция Media `202611220001`, новый Media; миграция Users
`202611220005`, остановка всех старых Users workers, новый API/worker. Новый worker
не делает fallback на старый endpoint. Legacy Media endpoint перестаёт принимать
изменения пользователя после первой versioned записи. Откат миграции Media при
наличии avatar-версий намеренно запрещён constraint; требуется forward fix.

Ограничения проверки: локальные PostgreSQL component и HTTP contract; реальные
S3/ClamAV, production outage и rollout не выполнялись.
